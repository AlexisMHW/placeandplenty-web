## Defects (severity, repro, fix suggestion; no SQL was changed)

**E-C1 (HIGH, money) Refunded-after-validation commission is still paid out (C9b).** Repro: purchase validated (45d passed), entitlement refunded, no `sweep_commissions` run yet, then `hc_create_payout_draft`. Observed: draft net 6200c includes the refunded commission (payable=1). Fix: in `hc_create_payout_draft` (and `hc_approve_payout`, `hc_record_external_payment`) exclude/hold any commission whose entitlement has `refunded_at`/`revoked_at` set or whose purchase fact is refunded, or call the refund/dispute reversal check inside the draft transaction; and schedule the sweep (see E-C2). Refund during the hold itself is handled (C9a/C10/C15).

**E-C2 (HIGH, wiring) Nothing calls `sweep_commissions` or reconcile on a purchase.** Code scan: no cron/edge/scheduler invokes the sweep, and the purchase webhook does not call `record_purchase_facts` / `reconcile_commission_for_entitlement`; the DB functions work when driven (service role) but commissions never accrue or validate in production. Fix: call reconcile from the payment webhook path after `apply_payment_event`, and add a daily scheduled `sweep_commissions(now())`. Emulated here by calling the functions directly.

**E-D1 (MEDIUM) Paid payout with NULL reference can be inserted by service_role (D8).** The guard is a BEFORE UPDATE trigger only. Fix: add `CHECK (status <> 'paid' OR (external_reference is not null and length(btrim(external_reference))>=3 and paid_on is not null and payment_method is not null and confirmed_by is not null))` (NOT VALID then VALIDATE), and extend the guard trigger to BEFORE INSERT.

**E-D2 (LOW/DESIGN) Payout ledger readable by manager (D12).** Manager (hc.read, no hc.payout) can list payouts. Fix if payouts are owner-only: gate the payout list RPC/policy with `staff_has_permission('hc.payout')`; otherwise document that hc.read covers payout history.

**E-D3 (KNOWN GAP, MEDIUM) No Command Center action/screen calls `hc_settle_clawback` (D10d).** Settlement works only by RPC/SQL. Fix: add an owner-only action + confirmation form (reference, note, confirm) on the payouts page.

**E-B1 (MEDIUM) Manager cannot rename/edit a tier once it is paid-eligible (B8).** The manager form omits the eligibility field so `hc_tier_write` sees a change from true to false and returns `not_authorized_referral_eligibility`. Fix: web `saveTier` must pass the existing value when the actor lacks the permission (or hc_tier_write should treat an omitted/NULL eligibility as "unchanged").

**E-B2 (MEDIUM) Owner re-saving the tier form with the box unticked silently turns paid eligibility OFF (B9).** Fix: load the current value into the checkbox, and require a changed-eligibility reason/confirmation; fail closed on missing field (`undefined` must not mean false).
